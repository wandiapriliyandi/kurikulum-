Tujuan Pembelajaran

  • TP-5: Peserta didik mampu memahami konsep keamanan siber lanjutan (Zero Trust, manajemen kerentanan, kriptografi kunci publik) dan infrastruktur komputasi awan modern (virtualisasi, kontainer Docker pengantar, skalabilitas).
  • Indikator:
  1. Membedakan konsep Virtual Machine dan Containerisasi (Docker).
  2. Menjelaskan konsep skalabilitas sistem komputasi awan saat menghadapi peningkatan beban pengguna.

Materi Pokok

1. Virtualisasi Mesin (Virtual Machine / VM)

Virtualisasi perangkat keras memungkinkan satu mesin fisik (*host*) menjalankan beberapa sistem operasi tamu (*guest OS*) secara mandiri. Lapisan perantara yang bertugas mengelola alokasi CPU, RAM, penyimpanan, dan jaringan untuk tiap VM disebut Hypervisor (contoh: KVM, Proxmox, VirtualBox).

  • Karakteristik: Setiap VM mengemas kernel OS sendiri secara utuh.
  • Kelebihan: Isolasi keamanan sangat kuat pada level OS.
  • Kekurangan: Ukuran *image* besar (gigabyte), konsumsi RAM besar, serta waktu *booting* lambat (hitungan menit).

2. Isolasi Lingkungan Aplikasi melalui Kontainer (Docker)

Kontainerisasi merupakan virtualisasi tingkat sistem operasi (*OS-level virtualization*). Kontainer berjalan di atas *engine* kontainer (seperti Docker) dan berbagi kernel OS induk yang sama, namun lingkungan aplikasi, dependensi pustaka (*libraries*), dan jaringannya tetap terisolasi.

  • Karakteristik: Hanya mengemas aplikasi dan pustaka pendukung tanpa memuat kernel OS tamu.
  • Kelebihan: Ukuran *image* sangat ringan (megabyte), proses *start-up* instan (hitungan detik), hemat memori, dan portabel (*write once, run anywhere*).

3. Perbandingan Utama VM vs Kontainer

  • Arsitektur: VM memakai Hypervisor + Guest OS utuh; Kontainer memakai Container Engine + *shared kernel*.
  • Efisiensi: VM memakan ruang disk dan RAM besar; Kontainer sangat ringkas dan hemat sumber daya.
  • Kecepatan Start: VM butuh hitungan menit; Kontainer aktif dalam hitungan detik.

4. Skalabilitas Cloud: Scale Up vs Scale Out

Skalabilitas adalah kemampuan sistem cloud mempertahankan performa saat lonjakan beban akses pengguna terjadi.

  • Scale Up (Skalabilitas Vertikal):
  • Menambah spesifikasi perangkat keras pada satu mesin/server yang ada (misal menaikkan RAM dari 16 GB ke 64 GB atau menambah inti CPU).
  • *Sifat:* Pengaturan mudah, tetapi memiliki batas fisik perangkat keras (*hardware limit*) dan memerlukan waktu henti (*downtime*) saat pemutakhiran.
  • Scale Out (Skalabilitas Horizontal):
  • Menambah jumlah unit server baru yang bekerja bersama secara paralel, didistribusikan melalui *Load Balancer*.
  • *Sifat:* Sangat fleksibel, mendukung penggandaan otomatis (*auto-scaling*), serta memiliki keandalan tinggi (*high availability*) karena matinya satu server tidak mematikan sistem secara menyeluruh.

Kegiatan Pembelajaran

Pendahuluan (±10 menit)

  1. Pembukaan: Guru mengucap salam, mengajak santri berdoa bersama, dan mengecek kehadiran.
  2. Apersepsi Kontekstual Pesantren: Guru mengajukan pemantik:

*"Saat pendaftaran santri baru (PSB) atau pendaftaran kepulangan santri dibuka online serentak, ribuan wali santri mengakses web secara bersamaan sehingga server lambat atau error. Mengapa server bisa tumbang dan bagaimana solusinya?"*

  1. Penyampaian Tujuan: Guru menyampaikan materi hari ini: memahami perbedaan VM dan Docker serta strategi skalabilitas server cloud.

Inti (±40 menit) — Kontekstual Kehidupan Pesantren

*(Dirancang adaptif: simulasi unplugged tanpa komputer, atau demonstrasi jika proyektor tersedia).*

  1. Eksplorasi Konsep (10 menit):
  • Guru menguraikan arsitektur dengan analogi pesantren:
  • VM = Kompleks Perumahan Guru: Masing-masing rumah memiliki pondasi, atap, dapur, dan kamar mandi sendiri (OS terpisah). Mandiri namun memakan lahan luas dan mahal.
  • Docker = Kamar Asrama Santri: Gedung asrama berbagi atap, pondasi, dan listrik yang sama (*shared kernel*), namun tiap kamar bersekat rapi dan punya kunci privasi tersendiri (*container isolation*). Sangat hemat tempat dan fleksibel.
  1. Aktivitas Unplugged: Simulasi Skalabilitas PSB (15 menit):
  • Guru menunjuk 1 santri menjadi "Server Website PSB".
  • 5 santri maju menyerahkan berkas pendaftaran (server melayani lancar).
  • Guru memanggil 20 santri menyerbu serentak (server kewalahan dan macet/*overload*).
  • Santri mendiskusikan dua jalan keluar:
  • Opsi Scale Up: Memberi santri server meja lebih lebar dan 2 pulpen (meningkatkan kapasitas satu orang, namun tetap ada batas stamina fisik).
  • Opsi Scale Out: Menambah 3 santri server baru di sampingnya dan menunjuk 1 santri sebagai *Load Balancer* untuk membagikan antrean wali santri secara merata ke keempat meja.
  1. Diskusi & Sintesis (10 menit):
  • Santri menganalisis bahwa Docker sangat ideal untuk *Scale Out* karena kontainer aplikasi web dapat digandakan puluhan unit dalam hitungan detik saat pendaftaran memuncak, lalu dinonaktifkan kembali saat malam sepi untuk menghemat biaya.
  1. Penguatan Materi (5 menit):
  • Guru meluruskan kesalahpahaman dan memantapkan poin pembeda arsitektur isolasi dan strategi beban cloud.

Penutup (±10 menit)

  1. Refleksi Santri: Guru meminta 2 santri merangkum inti pelajaran dan mengaitkannya dengan prinsip kehati-hatian (*itqan*) dan efisiensi dalam mengelola sumber daya.
  2. Umpan Balik Singkat: Guru menguji pemahaman dengan tanya-jawab kilat.
  3. Penutup: Guru menyampaikan gambaran topik pekan depan, memimpin doa kafaratul majelis, dan menutup dengan salam.

Asesmen

1. Soal Latihan Singkat

Jawablah pertanyaan berikut secara ringkas:

  1. Mengapa kontainer Docker jauh lebih ringan dan cepat dijalankan dibandingkan Virtual Machine konvensional?
  2. Server ujian CBT madrasah melambat akibat diakses 500 santri serentak. Jelaskan perbedaan tindakan teknisi jika menerapkan solusi Scale Up dibandingkan Scale Out!

2. Kunci Jawaban

  1. Kontainer Docker tidak mengemas sistem operasi tamu (*guest OS*) beserta kernelnya secara utuh, melainkan berbagi kernel sistem operasi mesin induk (*host*). Kontainer hanya membungkus berkas aplikasi dan dependensi pustakanya saja, sehingga ukurannya kecil (MB) dan proses *start-up* tidak melewati *booting* OS.
  2. - Scale Up: Teknisi meningkatkan spesifikasi server tunggal tersebut (misalnya menambah kapasitas RAM atau mengganti CPU yang lebih tinggi).
  • Scale Out: Teknisi menambah beberapa unit server baru dan memasang *Load Balancer* di depannya untuk mendistribusikan beban akses santri secara merata.

3. Kriteria Ketuntasan

  • Tuntas (Skor ≥ 75): Mampu membedakan VM dan kontainer berdasarkan arsitektur kernel/sumber daya, serta mampu membedakan konsep penambahan spesifikasi (*scale up*) vs penambahan unit (*scale out*).
  • Belum Tuntas (Skor < 75): Masih tertukar antara fungsi kontainer dengan VM atau antara *scale up* dan *scale out*. Diberikan bimbingan remedial melalui telaah analogi asrama.
